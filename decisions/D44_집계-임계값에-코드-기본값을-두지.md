## D44. 집계 임계값에 코드 기본값을 두지 않는다 (2026-08-27)

**결정.** `AnalysisConfig` 는 `analysis_config` 테이블의 여섯 키를 전부 요구한다.
하나라도 없으면 던진다. 코드에 기본값이 없다.

**이유.** 기본값을 두면 임계값이 시드(V1)와 코드에 두 벌이 되어 반드시 어긋난다 —
루트의 `schema.sql` 을 없앤 것과 같은 이유다. 그리고 키가 빠졌을 때 조용히 기본값으로
넘어가면 **"설정을 바꿨는데 결과가 안 바뀐다"** 가 되는데, 로그만 보면 성공이다.
빈 `TFM_SAVE_DIR` 가 현재 작업 디렉터리를 감시하게 만든 것과 정확히 같은 모양이다.

**모르는 키는 무시한다.** 설정 항목을 추가하는 마이그레이션이 구버전 앱의 기동을 막을
이유가 없다. 없는 것은 위험하고 남는 것은 위험하지 않다 — 대칭이 아니다.

**뒤집힐 조건.** 없다. 이건 D15 의 "`analysis_config` 로 빼서 조정 가능하게 둔다" 를
실제로 성립시키는 조건이다.
