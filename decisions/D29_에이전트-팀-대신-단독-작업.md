## D29. 에이전트 팀 대신 단독 작업 + `agy` 검증 (2026-08-25)

**변경.** `project.md` 가 6명 에이전트 분업(설계·백엔드·프론트·QA)을 상정했다.
**혼자 구현하고, 읽기 전용 검증만 `agy`(Antigravity CLI) 서브에이전트에 넘긴다.**

**근거.** 이 프로젝트는 나누기 나쁜 모양이다. 어려운 부분(카운터·시너지·2단 축소)은
결정들이 서로 얽혀 있어 한 사람 머릿속에 있어야 하고, 나눌 수 있는 부분(Spring
보일러플레이트)은 애초에 어렵지 않다. D22 가 이미 같은 위험을 지적했다 —
"보일러플레이트에 에너지를 다 쓰고 정작 분석에 도달하지 못하는 것이 최대 위험."
분업은 조율 비용으로 그 위험을 키운다.

**`agy` 가 맞는 자리.** 파일을 많이 읽어야 하는 읽기 전용 작업이다. 컨텍스트를 많이
먹지만 판단은 필요 없는 일 — Java 출력과 Python 레퍼런스 대조, 골든 파일 회귀,
구현이 `decision.md` 의 결정과 어긋나지 않는지 대조, 저장소 훑기.
설계 판단·구현·최종 결정은 넘기지 않는다.
