## D55. 팀 이름은 `common.data` 에서 온다. 적재 시점에 슬롯별로 박아 넣는다 (2026-08-29)

**논점.** D54 가 팀을 적재했지만 이름이 없어 화면에 `팀 36` 으로만 보였다. 세이브 파일을
바이트로 뒤져도 이름이 없다 — `Seorabal` · `Gen.G` · `Griffin` 어느 것도 안 나온다.

**찾았다 — 세이브 폴더의 `common.data` 다.** 세이브와 같은 NRBF 라 파서를 그대로 쓴다.

```
CommonStore
 ├ TeamName   : String              ← 플레이어 팀 (번호 0)
 ├ CoachName  : String
 └ AITeamData : AITeamListData
     ├ Name : String                ← 프로필 이름
     └ Data : Dictionary<int, AITeamData>
         └ KeyValuePairs[] { key, value } → AITeamData { Name, Logo }
```

**딕셔너리의 키가 곧 `game_team_id` 다.** 실측: AI 팀 52개, 번호 1~56 에 구멍 넷(8·19·30·41).
플레이어 팀(0)은 딕셔너리가 아니라 `CommonStore` 뿌리에 있다.

**구멍이 테스트의 근거가 됐다.** 배열 인덱스를 번호로 쓰면 키가 0..51 로 촘촘해진다.
`최대 번호 > 팀 수` 를 단언하면 그 실수가 바로 잡힌다 — 개수만 세는 단언으로는 못 잡는다.

**이 파일은 커리어와 무관하게 바뀐다. 그게 문제의 전부다.**

사용자가 게임에서 팀을 커스터마이즈하면 그 자리에서 갈린다. 실제로 이번에 그랬고,
**결과가 이미 관측됐다.** 커리어의 정규리그 10팀(번호 0·27·29·31~37) 중 66세트를 뛴 35번은
지금 이름표에서 `dd` 다 — 사용자가 방금 넣은 자리표시자다. 27·29·31~37 도 지금은
`Lyon Gaming` · `Chiefs Esports Club` · `KT Rolster` · `Dplus KIA` · `JD Gaming` · `Invictus
Gaming` · `dd` · `Karmine Corp` · `Cloud 9` 로, 한 리그로 보기 어려운 조합이다.

**즉 지금 이름표는 지나간 커리어의 이름이 아니다.** D53 이 패치에서 잡아낸 것과 같은 형태다 —
*같은 번호가 시점마다 다른 대상을 가리킨다.*

**결정 1 — 화면에서 실시간으로 읽지 않는다. 적재 시점에 `team.name` 에 박는다.**
`team` 의 자연키가 `(slot_id, game_team_id)` 이고 `name` 도 슬롯별이라, 커리어마다 그때의
이름을 따로 담을 수 있다. 실시간 조회로 두면 프로필을 만질 때마다 **과거 표의 이름이 통째로
바뀐다.**

**결정 2 — 이미 붙은 이름은 절대 덮지 않는다.** `Team.nameIfAbsent` 가 그걸 강제한다.
덮기 시작하면 결정 1이 무의미해진다. 재적재도 이름을 바꾸지 못한다.

**결정 3 — 이미 지나간 커리어 2개의 이름은 틀릴 수 있다는 것을 받아들인다.**
당시 이름은 어디에도 남아 있지 않아 복구할 방법이 없다. 화면에 "현재 프로필 기준" 을
표시하는 선에서 감수한다. **앞으로 적재되는 커리어부터는 정확하다.**

**결정 4 — 이름표가 없거나 깨져도 적재를 멈추지 않는다.** 이름은 표시용이고 경기가 본체다.
게임이 그 파일 형식을 바꿨다고 공식 경기 수백 건을 못 넣게 되는 쪽이 훨씬 나쁘다.
**대신 조용히 넘어가지 않는다** — 경로와 원인을 WARN 으로 남기고, 결과는 화면에 이름 없는
팀으로 그대로 드러난다. 삼키는 것과 다른 점이 그것이다.

**빈 문자열을 이름으로 두지 않는다.** `nameOf` 가 `Optional` 을 돌려주고 공백은 비어 있는
것으로 친다. 빈 이름을 붙이면 화면에서 "이름 없는 팀" 과 "이름이 있는 팀" 이 같아 보인다.

**검증.** DB 없이 도는 테스트 8개(`CommonDataParserTest` 5 · `TeamRegistryTest` 3 추가)를
변조 2종으로 확인했다 — 이름 무조건 덮어쓰기, 0번을 딕셔너리에서 찾기. 둘 다 잡혔다.
픽스처가 필요한 1개는 메인에서 돌려야 한다.

**뒤집힐 조건.** 게임이 세이브 안에 팀 이름을 넣기 시작하면 결정 1~3 이 전부 필요 없어진다.
`common.data` 에 프로필 변경 이력이 있다면 결정 3 도 다시 본다.
