`slot_638683` 만 294/181 로 문서(289/177)보다 크다. 그 세이브는 문서 작성 뒤에도
플레이돼서 파일이 갱신됐다(수정일 8/11, 나머지 둘은 1/26). 파서 문제가 아니다.

**골든 파일의 계약은 바이트 일치다.** JSON 을 정규형으로만 쓴다 — 키 정렬,
UTF-8 그대로, 구분자 고정, 개행 LF. Java 의 직렬화도 이 형태를 맞춰야 한다.
`make_baseline.py --check` 가 재생성 없이 해시로 대조한다.

**설계에서 걸린 것 하나.** .NET enum 은 `{value__: 0}` 짜리 객체로 직렬화된다.
`TeamType` 이 그래서 JSON 으로 나가지 않았다. 풀지 않으면 값 비교도 안 되므로
**모든 enum 을 정수로 되돌리는 것을 파서 계층에서 처리**했다. `ChampionCategory` 등도 같은 모양이다.

**리스트 길이를 `_items` 로 세면 틀린다.** .NET `List<T>` 는 용량 여유분을 뒤에 `null` 로
달고 있어서 `_size` 만큼만 유효하다. 밴 2개인 경기가 `['A','B',null,null]` 로 보이는 이유다.

**다음.** 이제 Java 파서를 짤 수 있다. 다만 골든 파일이 막아주는 범위는 생각보다 좁다 — D34.
