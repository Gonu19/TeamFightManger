## D12. 실시간 = 세이브 파일 쓰기 감지

**측정.** 파싱이 전체 0.39초, 경기 스트림만 0.15초다. 파일 감시 → 재파싱 → 신규 경기 diff →
DB → 화면 갱신 전체가 1초 안에 끝난다. **병목은 우리 쪽이 아니라 게임이 세이브를 쓰는 주기다.**

**설계.**
- 트리거는 "게임이 세이브 파일에 쓰는 순간". 유저는 웹에서 아무것도 누르지 않는다
- 쓰기 도중에 읽으면 스트림이 잘린다 → 마지막 변경 후 1.5초 조용하면 읽는 디바운스 필요
- diff 는 `GameStat.ID` 기준. 이미 넣은 ID는 건너뛴다

**미확정.** 게임이 세이브를 얼마나 자주 쓰는지, 실행 중 파일이 잠기는지는 아직 측정 전이다.
`tools/watch_save.py` 로 측정한다. 결과에 따라:

| 관측 | 결론 |
|---|---|
| 경기일마다 쓰기 | 실시간(경기일 단위) 성립 |
| 저장 눌러야 쓰기 | 준실시간. 유저 저장 습관에 의존 |
| 종료 시에만 쓰기 | 세션 단위 배치로 설계 변경 |

**이 결과는 구현 방식만 바꾸고 스키마는 바꾸지 않는다.**
