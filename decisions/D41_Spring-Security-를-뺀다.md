## D41. Spring Security 를 뺀다 (2026-08-27)

**증상.** 기동할 때마다 로그에 이런 것이 떴다.

```
Using generated security password: 766754c1-9335-49a7-a09c-e68774c9261b
```

`spring-boot-starter-security` 가 의존성에 있어서 자동설정이 붙었다. 화면이 없어 지금은
무해하지만, `/tier` 를 만드는 순간 **기동할 때마다 바뀌는 UUID 를 물어보는 로그인 창**이
앞을 막는다. 소스에는 security 참조가 한 줄도 없었다 — 쓰려고 넣은 게 아니라
Initializr 에서 딸려온 것으로 보인다.

**결정.** 의존성을 뺀다. `spring-boot-starter-security` 와 `spring-security-test` 둘 다.

**이유.** D27 과 같은 자리다. 이건 로컬 `java -jar` 이고, 세이브 파일 옆에서 도는
단일 사용자 앱이라 인증할 상대가 없다. 사용자 판단도 같았다 — "어차피 이 컴퓨터에서만 한다".

**`permitAll()` 로 열어두지 않은 이유.** 그러면 "보안이 있는데 다 열어놨다" 가 된다.
실제로는 없는 방어선을 있는 것처럼 보이게 하는 것이고, `tfm.read-only` 가
선언만 있고 강제되지 않는 것(D38)과 같은 종류의 착시다. 없는 것은 없어야 한다.

**뒤집힐 조건.** 이 앱을 이 PC 밖에서 띄우게 되면. 그때는 노출면이 완전히 달라지므로
`permitAll()` 을 되돌리는 게 아니라 처음부터 다시 설계해야 한다. 로컬 전제(D22·D27)가
깨지는 것이므로 그쪽 결정이 먼저 뒤집힌다.
